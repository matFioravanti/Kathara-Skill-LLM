# Specifica DNS: gerarchia interna per il lab static-routing

Nel laboratorio Kathara esistente va configurata una gerarchia DNS interna usando la topologia e gli indirizzi già presenti. Il lab contiene cinque router (`r1`–`r5`) e gli host `pc1`–`pc10`; il routing statico IPv4/IPv6 deve restare invariato.

## Requisiti (MUST)

### Ruoli e zone
- `pc2` (`100.0.6.2`): server autoritativo esclusivamente per la zona radice `.` raggiungibile via IPv4.
- `pc8` (`2001:db8:2::8`): server autoritativo esclusivamente per la zona `test.`, delegata dalla root servita da `pc2` tramite record NS e glue AAAA per `pc8`.
- `pc3` (`100.0.0.2`, `2001:db8:3::2`): resolver ricorsivo dual-stack per i client. Deve raggiungere la root interna su `pc2` usando root hints e seguire la delega verso `pc8`, senza forwarder.
- `pc9` (`2001:db8:4::9`): web server HTTP IPv6 raggiungibile all'indirizzo `http://[2001:db8:4::9]/`.

### Record DNS
- La zona `test.` su `pc8` deve contenere `www.test. AAAA 2001:db8:4::9`.
- La root su `pc2` deve delegare `test.` a `pc8` con il record NS e il glue AAAA necessario per raggiungere `2001:db8:2::8`.
- Configura `pc3` con una zona root di tipo hint che indirizzi la root interna su `100.0.6.2`; non inserire root server pubblici.
- Su `pc3` disattiva la validazione DNSSEC con `dnssec-validation no;`.

### Client e verifica del servizio
- `pc4` (`200.0.6.2`) usa `pc3` come resolver tramite IPv4 (`100.0.0.2`) e deve risolvere `www.test.` attraverso la gerarchia DNS interna. Essendo IPv4-only, non deve essere modificato per raggiungere artificialmente il web server IPv6.
- `pc6` (`2001:db8:3::6`) è IPv6-only e usa `pc3` tramite IPv6 (`2001:db8:3::2`); deve risolvere `www.test.` e poter raggiungere il web server IPv6.
- Verifica che il servizio HTTP di `pc9` risponda con stato 200 su `http://[2001:db8:4::9]/`.

## Vincoli (MUST NOT)

### Vincoli generali
- Non modificare `lab.conf`, la topologia, il routing statico, i gateway o gli indirizzi IP già assegnati.
- Non aggiungere host, link, interfacce, indirizzi o rotte.
- Non usare forwarder, DNS pubblici o root hint pubblici.
- Non configurare risposte statiche in `/etc/hosts` per `www.test.`.
- Non assegnare più ruoli DNS alla stessa macchina e non configurare i router come server DNS.

### `pc2` — Root DNS
- Non deve essere autoritativo per `test.`.
- Non deve offrire ricorsione ai client.

### `pc8` — Autoritativo per `test.`
- Non deve essere configurato come root DNS o resolver ricorsivo.
- Non deve essere autoritativo per la zona radice `.`.

### `pc3` — Resolver
- Non deve essere autoritativo per `.` né per `test.`.
- Non deve usare forwarder o configurazioni che aggirino la delega interna.

### Client
- I client devono interrogare `pc3`, non `pc2` o `pc8` direttamente.
- `pc4` deve restare IPv4-only e `pc6` deve restare IPv6-only; non aggiungere indirizzi o rotte dell'altra famiglia per aggirare i requisiti.
