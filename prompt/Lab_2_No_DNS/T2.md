Nel laboratorio Kathara esistente configura il DNS gerarchico interno rispettando la topologia a cinque router, i dieci host e il routing statico IPv4/IPv6 già presenti.

Fai:
- Configura `pc2` (`100.0.6.2`) come server autoritativo per la sola zona radice `.` via IPv4.
- Configura `pc8` (`2001:db8:2::8`) come server autoritativo per la sola zona `test.` e delega `test.` dalla root con record NS e glue AAAA verso `2001:db8:2::8`.
- Configura `pc3` (`100.0.0.2`, `2001:db8:3::2`) come resolver ricorsivo dual-stack che usa una root hint interna verso `pc2`, senza forwarder e con `dnssec-validation no;`.
- Nella zona `test.` crea il record `www.test. AAAA 2001:db8:4::9`.
- Mantieni attivo un web server su `pc9` (`2001:db8:4::9`) e verifica la risposta HTTP su `http://[2001:db8:4::9]/`.
- Configura `pc4` per usare il resolver `pc3` via IPv4 (`100.0.0.2`) e `pc6`, IPv6-only, per usarlo via IPv6 (`2001:db8:3::2`). Entrambi devono risolvere `www.test.` attraverso la gerarchia DNS interna; solo `pc6` deve poter raggiungere il web server IPv6.

Non fare:
- Non modificare topologia, `lab.conf`, indirizzi, gateway o routing statico; non aggiungere interfacce o rotte.
- Non usare forwarder, DNS pubblici o root hint pubblici.
- Non rendere `pc2` autoritativo per `test.` o ricorsivo; non rendere `pc8` root o ricorsivo; non rendere `pc3` autoritativo.
- Non far interrogare direttamente ai client `pc2` o `pc8`.
- Non aggiungere record A per `www.test.` né risposte in `/etc/hosts`; `pc4` deve restare IPv4-only e `pc6` IPv6-only.
