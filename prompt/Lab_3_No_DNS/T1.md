# Specifica DNS avanzata: gerarchia interna ridondata e servizi dual-stack

Nel laboratorio Kathara esistente va configurata una gerarchia DNS interna più articolata usando esclusivamente la topologia e gli indirizzi già presenti. Il lab contiene sette router (`r1`–`r7`) e gli host `pc1`–`pc14`; il routing statico IPv4/IPv6 deve restare invariato.

## Requisiti (MUST)

### Ruoli DNS
- `pc2` (`100.0.6.2`): server autoritativo esclusivamente per la zona radice `.` raggiungibile via IPv4.
- `pc8` (`2001:db8:2::8`): server primario autoritativo per la zona `test.` raggiungibile via IPv6.
- `pc10` (`2001:db8:5::10`): server secondario autoritativo per `test.`; deve ottenere la zona da `pc8` tramite trasferimento di zona e non deve essere configurato come master.
- `pc11` (`200.0.11.2`): server autoritativo esclusivamente per la sottozona `services.test.` raggiungibile via IPv4.
- `pc3` (`100.0.0.2`, `2001:db8:3::2`): resolver ricorsivo dual-stack per i client. Deve partire esclusivamente dalla root interna su `pc2`, seguire la delega verso `test.` e successivamente quella verso `services.test.`, senza forwarder.

### Delega e ridondanza
- La root su `pc2` deve delegare `test.` a entrambi i nameserver autoritativi `pc8` e `pc10`, con record NS e glue AAAA corretti.
- `pc8` deve consentire il trasferimento della zona `test.` esclusivamente a `pc10`.
- `pc10` deve servire gli stessi dati autoritativi di `pc8` anche se il primario non viene interrogato direttamente dai client.
- La zona `test.` deve delegare `services.test.` a `pc11` tramite record NS e glue A verso `200.0.11.2`.

### Record della zona `test.`
- Crea `www.test. A 100.0.12.2`.
- Crea `www.test. AAAA 2001:db8:4::9`.
- Crea `portal.test. CNAME www.test.`.
- Crea un record MX per `test.` con preferenza `10` verso `mail.services.test.`.
- Crea `_http._tcp.test. SRV 0 5 80 www.test.`.
- Crea `test. TXT "benchmark=dns-advanced"`.

### Record della zona `services.test.`
- Crea `mail.services.test. A 200.0.11.2`.
- Crea `status.services.test. A 200.0.1.2`.
- La zona deve essere servita soltanto da `pc11`.

### Resolver
- Configura `pc3` con una zona root di tipo hint che punti esclusivamente alla root interna `100.0.6.2`; non inserire root server pubblici.
- Non configurare forwarder.
- Imposta `dnssec-validation no;`.
- Il resolver deve poter attraversare correttamente una catena mista IPv4 → IPv6 → IPv4: root su `pc2`, zona `test.` su `pc8`/`pc10`, sottozona `services.test.` su `pc11`.

### Servizi HTTP e client
- `pc12` (`100.0.12.2`) deve offrire HTTP IPv4 per `www.test.`.
- `pc9` (`2001:db8:4::9`) deve offrire HTTP IPv6 per `www.test.`.
- `pc1` (`200.0.1.2`) deve offrire un servizio HTTP per `status.services.test.`.
- `pc4` (`200.0.6.2`) usa `pc3` come resolver via IPv4 (`100.0.0.2`): deve risolvere `www.test.`, ottenere il record A e raggiungere il servizio HTTP IPv4.
- `pc6` (`2001:db8:3::6`) usa `pc3` come resolver via IPv6 (`2001:db8:3::2`): deve risolvere `www.test.`, ottenere il record AAAA e raggiungere il servizio HTTP IPv6.
- Entrambi i client devono risolvere `portal.test.`, il record MX di `test.`, il record SRV e `status.services.test.` tramite il resolver.

## Vincoli (MUST NOT)

### Vincoli generali
- Non modificare `lab.conf`, topologia, collision domain, indirizzi, gateway o routing statico.
- Non aggiungere host, link, interfacce, indirizzi o rotte.
- Non usare forwarder, DNS pubblici o root hint pubblici.
- Non inserire `www.test.`, `portal.test.` o `status.services.test.` in `/etc/hosts`.
- Non configurare i router come server DNS.
- Non assegnare a una macchina più ruoli DNS tra root, autoritativo `test.`, autoritativo `services.test.` e resolver.

### Separazione dei ruoli
- `pc2` non deve essere autoritativo per `test.` o `services.test.` e non deve offrire ricorsione.
- `pc8` non deve essere root, resolver ricorsivo o autoritativo per `services.test.`.
- `pc10` deve essere secondario per `test.` e non deve essere configurato come master o resolver.
- `pc11` non deve essere autoritativo per `.` o `test.` e non deve offrire ricorsione.
- `pc3` non deve essere autoritativo per `.`, `test.` o `services.test.`.

### Client
- I client devono interrogare `pc3` e non i server autoritativi direttamente.
- `pc4` deve restare IPv4-only e `pc6` IPv6-only: non aggiungere indirizzi o rotte dell'altra famiglia per aggirare i requisiti.
