# Specifica DNS avanzata — lab03_ladder8_dual

Nel laboratorio Kathara esistente `lab03_ladder8_dual` va configurata una gerarchia DNS interna avanzata usando esclusivamente la topologia e gli indirizzi già presenti. Il lab contiene 8 router e 16 host; il routing statico IPv4/IPv6 deve restare invariato.

## Requisiti (MUST)

### Ruoli DNS
- `pc1` (`10.33.0.10`): server autoritativo esclusivamente per la zona radice `.` raggiungibile via IPv4.
- `pc3` (`10.33.0.74`): server primario autoritativo per la zona `test.` raggiungibile via IPv4.
- `pc5` (`10.33.0.138`): server secondario autoritativo per `test.`; deve ottenere la zona da `pc3` tramite trasferimento di zona e non deve essere configurato come master.
- `pc7` (`10.33.0.202`): server autoritativo esclusivamente per la sottozona `services.test.` raggiungibile via IPv4.
- `pc9` (`10.33.1.10`): resolver ricorsivo per i client. Deve partire esclusivamente dalla root interna su `pc1`, seguire la delega verso `test.` e poi quella verso `services.test.`, senza forwarder.

### Delega e ridondanza
- La root su `pc1` deve delegare `test.` a entrambi i nameserver autoritativi `pc3` e `pc5`, con record NS `ns1.test.` e `ns2.test.` e glue A verso `10.33.0.74` e `10.33.0.138`.
- `pc3` deve consentire il trasferimento della zona `test.` esclusivamente a `pc5`.
- `pc5` deve servire gli stessi dati autoritativi del primario.
- La zona `test.` deve delegare `services.test.` a `pc7` tramite `ns.services.test.` e glue A verso `10.33.0.202`.

### Record della zona `test.`
- Crea `www.test. A 10.33.1.138`.
- Crea `www.test. AAAA 2001:db8:1300:7::10`.
- Crea `portal.test. CNAME www.test.`.
- Crea un record MX per `test.` con preferenza `10` verso `mail.services.test.`.
- Crea `_http._tcp.test. SRV 0 5 80 www.test.`.
- Crea `test. TXT "benchmark=dns-advanced"`.

### Record della zona `services.test.`
- Crea `mail.services.test. A 10.33.0.202`.
- Crea `status.services.test. A 10.33.1.202`.
- La zona deve essere servita soltanto dal server autoritativo assegnato alla sottozona.

### Resolver
- Configura `pc9` con una zona root di tipo hint che punti esclusivamente alla root interna `10.33.0.10`; non inserire root server pubblici.
- Non configurare forwarder.
- Imposta `dnssec-validation no;`.
- Il resolver deve seguire realmente le deleghe interne e non deve essere autoritativo per `.`, `test.` o `services.test.`.

### Servizi e client
- `pc13` (`10.33.1.138`) deve offrire HTTP IPv4 per `www.test.`.
- `pc16` (`2001:db8:1300:7::10`) deve offrire HTTP IPv6 per `www.test.`.
- `pc15` (`10.33.1.202`) deve offrire HTTP per `status.services.test.`.
- `pc11` (`10.33.1.74`) usa il resolver `pc9` via IPv4 (`10.33.1.10`); deve risolvere tutti i record richiesti e raggiungere `www.test.` via IPv4.
- I client devono risolvere anche `portal.test.`, il record MX di `test.`, il record SRV, il TXT e i nomi della sottozona `services.test.` tramite il resolver.

## Vincoli (MUST NOT)

### Vincoli generali
- Non modificare `lab.conf`, topologia, collision domain, indirizzi, gateway o routing statico.
- Non aggiungere host, link, interfacce, indirizzi o rotte.
- Non usare forwarder, DNS pubblici o root hint pubblici.
- Non inserire `www.test.`, `portal.test.`, `mail.services.test.` o `status.services.test.` in `/etc/hosts`.
- Non configurare i router come server DNS.
- Non assegnare a una macchina più ruoli DNS tra root, primario `test.`, secondario `test.`, autoritativo `services.test.` e resolver.

### Separazione dei ruoli
- `pc1` non deve essere autoritativo per `test.` o `services.test.` e non deve offrire ricorsione.
- `pc3` non deve essere root, resolver ricorsivo o autoritativo per `services.test.`.
- `pc5` deve essere secondario per `test.` e non deve essere configurato come master o resolver.
- `pc7` non deve essere autoritativo per `.` o `test.` e non deve offrire ricorsione.
- `pc9` non deve essere autoritativo per `.`, `test.` o `services.test.`.

### Client
- I client devono interrogare `pc9` e non i server autoritativi direttamente.
- `pc11` deve restare IPv4-only; non aggiungere configurazioni dell'altra famiglia IP per aggirare i requisiti.
