# Specifica DNS: DNS gerarchico dual-stack con web server

Nel laboratorio Kathara esistente va aggiunta una gerarchia DNS completamente interna, senza modificare la topologia, il routing statico o gli indirizzi già configurati.

## Requisiti (MUST)

### Ruoli e zone
- `pc2dual` (`10.2.0.30`, `fd00:2::30`): server autoritativo esclusivamente per la zona radice `.`.
- `pc5dual` (`10.5.0.30`, `fd00:5::30`): server autoritativo per la zona `test.`, delegata dalla root su `pc2dual` mediante record NS e glue record IPv4/IPv6 quando necessari.
- `pc3dual` (`10.3.0.30`, `fd00:3::30`): Local DNS / resolver ricorsivo. Deve risolvere i nomi partendo dalla root interna ospitata su `pc2dual`.
- `pc1dual` (`10.1.0.30`, `fd00:1::30`): web server per `www.test.`.

### Record
- Nella zona `test.` su `pc5dual`, `www.test.` deve risolvere verso `pc1dual` sia in IPv4 sia in IPv6:
  - record A → `10.1.0.30`
  - record AAAA → `fd00:1::30`
- La delega di `test.` dalla root deve permettere al resolver di raggiungere correttamente il name server autoritativo su `pc5dual`.

### Client
- `pc4v6` è il client di riferimento IPv6-only e deve usare `pc3dual` come resolver tramite `fd00:3::30`.
- Gli host IPv4-only devono usare `pc3dual` tramite `10.3.0.30`.
- Gli altri host IPv6 o dual-stack usati come client devono interrogare `pc3dual` tramite un indirizzo compatibile con il proprio stack.
- I client devono poter risolvere `www.test.` attraverso la catena `pc3dual` → `pc2dual` → `pc5dual` e raggiungere il web server con il protocollo disponibile.

## Vincoli (MUST NOT)

### Vincoli generali
- Non modificare `lab.conf`, collegamenti, routing statico, gateway o indirizzi IP già assegnati, salvo le sole modifiche necessarie a configurare i servizi e il resolver dei client.
- Non configurare forwarder, DNS pubblici o root DNS pubbliche.
- Non assegnare più ruoli DNS alla stessa macchina.

### `pc2dual` — Root DNS
- Non deve essere autoritativo per `test.`.
- Non deve funzionare come resolver ricorsivo per i client.

### `pc5dual` — Autoritativo per `test.`
- Non deve essere configurato come root DNS o resolver ricorsivo.
- Non deve essere autoritativo per la zona radice `.`.

### `pc3dual` — Local DNS / Resolver
- Non deve essere autoritativo per `.` né per `test.`.
- Non deve usare forwarder esterni, DNS pubblici, root pubbliche o configurazioni statiche che aggirino la gerarchia interna.

### `pc1dual` — Web Server
- Non deve svolgere alcun ruolo DNS autoritativo o ricorsivo.

### Client
- I client non devono interrogare direttamente `pc2dual` o `pc5dual`: devono usare `pc3dual` come resolver.
- `pc4v6` non deve ricevere indirizzi IPv4 e deve usare il resolver esclusivamente via IPv6.
