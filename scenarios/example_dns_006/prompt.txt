Aggiungi al laboratorio esistente un’infrastruttura DNS gerarchica e un semplice servizio web, utilizzando esclusivamente macchine, topologia, indirizzi e routing già presenti. Non modificare la rete né aggiungere nuove rotte.

La struttura deve essere:

* pc4 → Root DNS autoritativo per `.`
* pc1 → Name Server autoritativo per `test.`
* pc3 → Local DNS / Recursive Resolver
* pc5 → Web Server per `www.test.`

pc4 deve essere autoritativo esclusivamente per la root artificiale `.` e delegare `test.` a pc1 tramite record NS e glue record quando necessario. Non deve essere autoritativo per `test.` né funzionare come resolver dei client.

pc1 deve essere autoritativo per `test.` e contenere i record SOA, NS e il record A di `www.test.`, che deve puntare a pc5. pc1 non deve svolgere il ruolo di root DNS o resolver ricorsivo.

pc5 deve ospitare il servizio HTTP raggiungibile tramite `www.test.` e non deve svolgere alcuna funzione DNS.

pc3 deve essere il resolver locale dei client e iniziare la risoluzione dalla root artificiale pc4. Non deve essere autoritativo per `.` o `test.` e non deve utilizzare DNS pubblici, forwarder esterni o configurazioni che aggirino la gerarchia.

pc6, essendo IPv6-only, deve utilizzare pc3 come DNS tramite IPv6. Gli altri client devono utilizzare pc3 come resolver e non interrogare direttamente pc4 o pc1.

La risoluzione deve seguire:

`Client -> pc3 -> pc4 Root . -> pc1 Authoritative test. -> pc5 Web Server`

Installa e configura BIND9 sulle macchine DNS e il servizio HTTP su pc5, rendendo persistente la configurazione tramite i file `.startup` e i file necessari nelle directory Kathara.

Non modificare routing, indirizzi o topologia. Il risultato finale deve permettere ai client di risolvere `www.test.` tramite pc3 e raggiungere il servizio web su pc5.
