Aggiungi al laboratorio esistente un’infrastruttura DNS gerarchica e un semplice servizio web, utilizzando esclusivamente le macchine, la topologia, gli indirizzi e il routing già presenti. Non modificare la rete né aggiungere nuove rotte.

La struttura deve essere:

* pc2 → Root DNS autoritativo per `.`
* pc5 → Name Server autoritativo per `test.`
* pc3 → Local DNS / Recursive Resolver
* pc1 → Web Server per `www.test.`

pc2 deve essere autoritativo esclusivamente per la root artificiale `.` e deve delegare correttamente `test.` a pc5 tramite record NS e glue record quando necessario. pc2 non deve essere autoritativo per `test.` e non deve funzionare come resolver ricorsivo per i client.

pc5 deve essere autoritativo per `test.` e contenere i record SOA, NS e il record A di `www.test.`, che deve puntare a pc1. pc5 non deve essere root DNS, Local DNS o resolver ricorsivo.

pc1 deve ospitare il servizio HTTP raggiungibile tramite `www.test.`. pc1 non deve svolgere alcun ruolo DNS.

pc3 deve essere il resolver utilizzato dai client e deve iniziare la risoluzione dalla root artificiale pc2. Non deve essere autoritativo per `.` o `test.`, né utilizzare DNS pubblici, root pubbliche, forwarder esterni o configurazioni statiche che aggirino la gerarchia DNS.

pc6, essendo IPv6-only, deve utilizzare pc3 come DNS tramite IPv6. Gli altri client devono utilizzare pc3 come resolver locale e non devono interrogare direttamente pc2 o pc5.

La risoluzione deve seguire realmente:

`Client -> pc3 -> pc2 Root . -> pc5 Authoritative test. -> pc1 Web Server`

Installa e configura BIND9 su pc2, pc3 e pc5 e il servizio HTTP su pc1. Rendi persistente tutta la configurazione tramite i file `.startup` e i file necessari nelle directory Kathara.

Non modificare routing, indirizzi o topologia per far funzionare il DNS.

Disabilita la validazione DNSSEC sul resolver dove necessario, poiché la root artificiale non è firmata.

Il risultato finale deve permettere ai client di risolvere `www.test.` tramite pc3 e raggiungere il servizio web su pc1 attraversando realmente la gerarchia DNS configurata.
